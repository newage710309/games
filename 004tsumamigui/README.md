# さくらちゃんのこっそりつまみぐい 🌰

授業中、先生に見つからないように木の実をつまみ食いするタイミングゲーム。
昔のフラッシュゲーム「オフィちゅラブ」の遊び方（見張りがよそ見している間だけボタンを押す）を、
シマエナガの「さくらちゃん」と、ことりの学校に置きかえたもの。全 3 時間（面）で、時間内にどれだけ多く食べられるかを競う。

**TypeScript + Vite + Canvas2D** の完全クライアントサイド構成。キャラクターも背景も
画像ファイルを使わず、すべて Canvas2D のコードで描いている。

## 遊び方

| 操作 | PC | スマホ・タブレット |
|---|---|---|
| 食べる（押している間） | クリック / `Space` / `Enter` を押しっぱなし | 画面のどこでも押しっぱなし |
| スタート・決定 | クリック / `Space` / `Enter` | タップ |
| ポーズ | `P` / `Esc` / 左上の「❚❚」 | 左上の「❚❚」 |
| 消音 | `M` | ポーズ画面の「おと：ON／OFF」 |

- 押している間、さくらちゃんが机の上の木の実をついばむ。1 粒 10 点。手を放すと、すぐにまじめに勉強しているふりに戻る。
- 押しっぱなしで 2.2 秒食べ続けると、ほっぺがぱんぱんになって**ほおばりモード**（食べる速さが 2 倍、画面の縁がピンクに光る）。
  手を放すとほっぺは元に戻る。
- 先生がこちらを見ているときに押していたら見つかって**ゲームオーバー**（1 回で終わり、コンティニューなし）。
  見つかるかどうかは、そのとき押しているかどうかだけで決める（放したあとの戻りの動きは関係ない）。
- 授業中に押し始めた指だけを「食べる」に数える。スタートのタップや、よーいの間から押しっぱなしの指は数えない（押しなおす）。
- チャイムが鳴ったらその授業はおしまい（時間切れはミスではない）。点数を持ったまま休み時間のデモを見て次の授業へ。
- 3 時間目のあと、合計点でエンディングが 3 通りに分かれる。いちばん上の「きゅうしょくが はいらない！」（食べすぎ）だけがクリア。
- ハイスコアは端末に保存する（`localStorage`、見つかって終わった場合も記録）。

## 先生の動き

| 動き | 見ている？ | 予兆 |
|---|---|---|
| 黒板を見ながら説明（後ろ向き） | いいえ | ― |
| 振り向いてこちらを見る | **はい** | せき払い「ゴホン」＋首がぴくっと動く |
| フェイント（首が半分回って戻る） | いいえ | 振り向くときと同じ予兆（見分けられない） |
| 板書タイム：チョークを取る → 書く → チョークを置く「コトッ」→ 振り向く | 書いている間はいいえ | チョークを置く動き（置いたら必ず振り向く） |
| 見回りの先生（3 時間目）：通路を歩き、立ち止まって「！」を出してからこちらを見る | 見ている間は**はい** | 「！」の吹き出し |

- 予兆から実際に見るまでは、どの面でも 0.55 秒以上（`MIN_CUE_TIME`。人の反応とスマホのタッチの遅れのぶん）。
  予兆なしにいきなり見ることはない。面の設定がこれを下回ると、読み込み時にエラーにしている。
- チョークを取ったら、短くても必ず板書する。板書の前後にはチョークを取る・置く動きが必ず入る。
- 首を回しきる途中（6 割）から「見ている」になる。フェイントは 4 割までしか回さないので見つからない。

## 授業（面）

| 時間 | 授業 | 長さ | 予兆 | フェイント | 板書タイム | 見回り |
|---|---|---|---|---|---|---|
| 1 | こくご | 45 秒 | 0.9 秒 | なし | 多め（4〜6 秒） | なし |
| 2 | さんすう | 50 秒 | 0.7 秒 | 28% | ふつう（3〜6 秒） | なし |
| 3 | テスト | 60 秒 | 0.6 秒 | 30%（板書中のちら見もあり） | ふつう（3〜5 秒） | あり |

- 1 時間目のあと「やすみじかん」（校庭で雪だるま作り）、2 時間目のあと「きゅうしょくまえ」（木の実をおかわり）のデモ。
- エンディング：4,500 点未満「もうすこし たべたかったな…」、6,500 点未満「おなか いっぱい！」、6,500 点以上「きゅうしょくが はいらない！」（食べすぎて給食が入らない。クリア）。

先生の動きの数値は `src/game/stages.ts`、食べる速さ・点数・予兆の最低秒数は `src/game/constants.ts` にまとめてある。

### エンディングの点数の決め方

自動プレイ（乱数を変えて各 60 回）の点数分布から決めた。どの型も一度も見つからなかった（予兆から見られるまで最低 0.7 秒）。
クリアは「うまく遊べたときのごほうび」にして、ほおばりを使わないと真ん中にも届かないようにしている。

| プレイの型 | 中央値 | いちばん下 / 真ん中 / クリア（60 回中） |
|---|---|---|
| 予兆で 0.3 秒後に放し、安全になって 0.25 秒で押しなおす | 6,740 | 0 / 21 / 39 |
| 押しなおしが 0.6 秒後 | 6,000 | 0 / 45 / 15 |
| 押しなおしが 1.2 秒後（慎重） | 4,650 | 24 / 36 / 0 |
| 1.2 秒ごとに放してしまう（ほおばりを使わない） | 3,180 | 60 / 0 / 0 |

## 開発

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # 型チェック + dist/ に静的ファイルを出力
```

- 開発時は、コンソールの `__game`（ゲームの状態）と `__seededRandom`（乱数の固定）で動きを再現して確かめられる。
- `design.html`（開発サーバーの `/design.html`）は、キャラクターの表情・ポーズと場面の見本を並べたデザイン確認用のページ。ビルドには含めない。

## 公開

このリポジトリは**ソース管理用**。公開は会社サイトへ手動で配置する。

1. `npm run build`
2. `dist/` の中身を会社サイトの `files/games/004tsumamigui/` にコピー
3. 会社サイト側でコミットして push
