# さくらちゃんのもちつき 🌸

クマがつく杵のリズムに合わせ、さくらちゃんがタップでおもちを返すリズムゲーム。
調子に乗ったクマのフェイントにつられず、3 うす分のおもちをつき上げる。全 3 面。

**TypeScript + Vite + Canvas2D** の完全クライアントサイド構成。キャラクターも背景も
画像ファイルを使わず、すべて Canvas2D のコードで描いている（さくらちゃんと雪だるまの絵は雪玉ころがし（008）と同じ。クマはこの作品で新しく描いた）。

## 遊び方

| 操作 | PC | スマホ・タブレット（画面のどこでも） |
|---|---|---|
| おもちを返す・雪玉をはじく | クリック / `Space` | タップ |
| スタート・決定 | クリック / `Space` / `Enter` | タップ |
| ポーズ | `P` / `Esc` / 左上の「❚❚」 | 左上の「❚❚」 |
| 消音 | `M` | ポーズ画面の「おと：ON／OFF」 |

「ぺったん（クマがつく）→ はいっ（さくらちゃんが返す）」を 2 拍 1 組でくり返す。杵が上がっているあいだに、「はいっ」の拍でタップする。
音を消していても遊べるよう、臼のまわりの白い輪が的に重なる瞬間でタイミングを見せる。

| タイミング | 判定 | 結果 |
|---|---|---|
| ずれが ±0.05 秒以内 | ぴったり！ | 100 点。おもちがつやつやになる |
| ずれが ±0.135 秒以内 | よし | 50 点 |
| それより早い（0.22 秒まで）、または返しそこねる | ミス | おもちがさくらちゃんにくっつく |
| 杵が落ちてくる瞬間にタップする | ごつん！ | 目を回して、おもちもくっつく（ミス扱い） |

- スマホでは音も指も遅れがちなので、「遅い」側だけ判定を 0.03 秒広げている。タイミング調整の設定はない。
- どの拍からも遠いタップは空振りで、何も起きない。
- **3 回ミスするとおもちに埋まり、ゲームオーバー**（1 回で終わり、コンティニューなし）。くっついた数は面ごとに 0 に戻る。
- ぴったりが 8 回続くと、くっついたおもちが 1 つはがれる。
- 3 回目のミスでさくらちゃんの姿が消え、臼のおもちに目が現れる。クマが気づかずつこうとして「あっ」と止まる。

### クマのいたずら

| 名前 | 動き | 正しい対応 | 出る面 |
|---|---|---|---|
| ふつう | ぺったん → はいっ | 拍に合わせてタップ | 1 うすめ〜 |
| フェイント | 杵を振り上げたままニヤッと止まる（輪は赤い点線に「×」） | タップしない（つられると、ごつん！） | 1 うすめ後半〜 |
| はやつき | ぺたぺたっと 2 連続でつく（輪はピンク） | すばやく 2 回タップ | 2 うすめ〜 |
| ふりむき | よそ見しながらつく（輪がうすい） | 音や前のリズムを頼りにタップ | 2 うすめ後半〜 |
| 雪玉のじゃま | 雪だるまが臼へ雪玉を投げこむ | 拍の合間にタップしてはじく（はじきそこねるとミス） | 3 うすめ |

はじめて出てくるいたずらは、ゆっくりした「おてほん」で一度見せてから本番に入れる（おてほんのあいだのタップは判定しない）。
フェイントの赤い輪は 1.25 拍前（100 BPM で 0.75 秒、145 BPM で 0.52 秒）、雪玉は 1.15 秒前から見える。

| よし | 50 点 |
| フェイントをがまんする | 50 点 |
| 雪玉をはじく | 100 点 |

## 面

| 面 | 舞台 | 速さ（BPM） | つく回数 | 長さ（よーい・おてほんをふくむ） | ★★ / ★★★ のぴったりの割合 |
|---|---|---|---|---|---|
| 1 うすめ | 昼の森の広場 | 90 → 95 → 100 | 30 回 | 約 49 秒 | 50% / 80% |
| 2 うすめ | 夕方、見物の動物が増える | 105 → 112 → 120 | 40 回 | 約 53 秒 | 50% / 80% |
| 3 うすめ | 大みそかの夜、雪だるまが乱入 | 125 → 135 → 145 | 50 回 | 約 53 秒 | 50% / 90% |

速くなるところでは、クマが「のってきた！」と調子に乗る。クリアすれば ★ は必ずつく。
いたずらの回数は面ごとに決まっていて、並びは遊ぶたびに変わる（`src/game/stages.ts` の `arrange`）。
1 うすめのあとは「まだまだ！」、2 うすめのあとはカラスのつまみ食いで「もう 1 うす！」のデモ、
エンディングは初日の出の中で大きな鏡もちを作り、みかんが足りず、さくらちゃんがてっぺんにのって、みかんの代わりになる。

## 拍の時計

拍は `AudioContext.currentTime` を基準に刻み、タップの判定も同じ時計で行う（`Audio.now()`）。フレームは数えない。
音はこの時計で 0.2 秒先まで予約し、タップは押した瞬間（`pointerdown`）に、イベントが届くまでの遅れを差し引いて判定する。
音がまだ使えないあいだ（解錠前・非対応の環境）だけ `performance.now` で進み、切りかわっても時刻は飛ばない。
ポーズから戻るときは 1.2 秒巻きもどして、構えなおす時間を作る。

## 難しさの確認

数値は `src/game/stages.ts` にまとめてある。自動プレイ（`src/game/bot.ts`。譜面を読み、ゆらぎのある時刻にタップする。腕前はタップのずれの大きさとフェイントにつられる割合で分ける。各 30 回）での目安：

| ボット | ずれ（標準偏差） | つられる割合 | ぜんぶクリア | 2 うすめまで | 1 うすめまで | 0 | 1 うすめの星（★/★★/★★★） | 3 うすめの星（★/★★/★★★） |
|---|---|---|---|---|---|---|---|---|
| じょうず | 30ms | 2% | 30 回 | 0 回 | 0 回 | 0 回 | 0 / 1 / 29 | 0 / 20 / 10 |
| ふつう | 45ms | 8% | 23 回 | 6 回 | 1 回 | 0 回 | 0 / 23 / 7 | 0 / 23 / 0 |
| はじめて | 60ms | 20% | 0 回 | 11 回 | 15 回 | 4 回 | 2 / 24 / 0 | ー |

- 「はじめて」でも 1 うすめは 30 回中 26 回クリア。
- 3 うすめの ★★★ は「じょうず」で 30 回中 10 回、「ふつう」は 0 回。
- ボットは譜面を読んでいるので、見てから反応する遅れや、輪が見えにくいときの迷いは「ずれ」の大きさでしか表していない。人の遊びやすさは試遊で確かめる必要がある。
- はじめは「よし」の幅を ±0.12 秒にしていたが、「はじめて」の 1 うすめのクリアが 30 回中 22〜24 回だったので ±0.135 秒に広げた。

## 開発

```bash
npm install
npm run dev        # http://localhost:5173/
npm run build      # dist/ に出力（base: './' なのでサブパス配信でもそのまま動く）
```

- `?stage=3` をつけて開くと、その面から始まる（開発サーバーのときだけ）。
- `design.html`（開発時だけ）：場面ごとの画面と、さくらちゃん・クマ・杵と臼・おもち・輪・背景の一覧。
- 開発時はコンソールから `__game`（状態）、`__seededRandom`（乱数の固定）、`__render` を使える。
  自動プレイは `const { SKILLS, playOnce } = await import('/src/game/bot.ts')` を読みこんで、
  `playOnce(SKILLS['ふつう'], 1)`。
  （ハイスコアが localStorage に保存されるので、測ったあとは `localStorage.removeItem('sakura-mochitsuki.highscore.v1')` で消す）
